Web Development: Design, Develop and Manage Website – LO3

Client: TechHub

Project: Multi-page airline information and booking portal

Brand: SkyWay Airlines

1. Design Document (P5)

1.1 Client needs

  • A branded multipage website for TechHub to demonstrate a realistic travel/booking portal.
  • Accessible, responsive design that works on mobile and desktop.
  • Clear navigation across key pages: home, schedule, status, booking, manage booking, offers, account, admin, about, contact.
  • Interactive search, booking, and status features.
  • Branding consistent with professional airline-style visual identity.
  • External CSS and HTML5 semantics with modern usability.

1.2 User goals

  • Quickly search and find flights.
  • View full flight schedules and status updates.
  • Book a flight and receive confirmation.
  • Manage existing bookings using a PNR.
  • View account details and saved bookings.
  • Browse promotions and contact support.
  • Admin users can manage flights, bookings, offers, and customer messages.

1.3 Key pages and wireframes

The final website includes 9 interlinked pages:

  • Home (index.html)
  • Flight Schedule (flight-schedule.html)
  • Flight Status (flight-status.html)
  • Booking (booking.html)
  • Manage Booking (manage-booking.html)
  • Offers (offers.html)
  • User Dashboard (user-dashboard.html)
  • Admin Dashboard (admin-dashboard.html)

Wireframe descriptions:

  • Home: hero banner, flight search form, featured cards, flight table results.
  • Schedule: filter form and responsive schedule cards.
  • Status: two search panels and results area.
  • Booking: booking form, login requirement, confirmation modal with PNR.
  • Manage Booking: PNR lookup form and result area.
  • Offers: promotional cards and loyalty progress block.
  • User Dashboard: guest login/register and profile/bookings/favorites tabs.
  • Admin Dashboard: analytics cards and management tabs.
  • About: brand story and metrics cards.
  • Contact: contact form and contact information panel.

1.4 Navigation structure, layout grid, and content hierarchy

  • Primary menu: Home, Schedule, Status, Book, Manage, Offers, My Account, Admin, About, Contact.
  • Admin menu items are visible only to authenticated admin users.
  • Consistent footer on every page.

  • Hero section at top of each page to establish purpose.

3. Justification of Implementation (M4)

3.1 Page and layout decisions

The home page implements the wireframe with a prominent hero section, search form, featured cards, and a flight table. This keeps the main flight search actions visible and easy to use.

Schedule and status pages use card-based filters and results panels to match the documented content hierarchy, making it simple for users to find flights and status updates.

The booking page places the booking form centrally and adds a confirmation modal, supporting user confidence and clear next steps.

Separate account and admin pages provide distinct journeys for travellers and administrators.

3.2 Technology choices

Bootstrap was chosen to speed responsive development and ensure consistent layout across multiple pages. Custom CSS in styles.css provides brand styling while keeping styling separate from HTML.

JavaScript is modular and shared across pages, using DOM injection for common navigation and modals so updates stay consistent across the site.

Firebase placeholders support future backend connectivity for authentication and data storage.

3.3 Functionality adjustments

The implemented site preserves the medium-fidelity wireframe layout while simplifying some form interactions for usability. The admin dashboard was extended with additional analytics and management tabs to improve workflow clarity.

Shared page scaffolding in app.js reduces duplication and ensures a consistent site structure across multiple pages.

4. Evaluation of Design & Development Process (D2)

4.1 Alignment with the design document

  • The final website delivers a branded multipage site with navigation, hero sections, forms, cards, and interactive features.
  • More than the required 7–10 pages are present, including home, schedule, status, booking, manage, offers, user account, admin, about, and contact.
  • Client requirements for a professional branded portal are met through consistent color, typography, and layout.

4.2 Technical challenges

  • Keeping common navigation and modals consistent across pages required a shared JavaScript approach.
  • Responsive layout across many page types required careful Bootstrap grid use and custom CSS adjustments.
  • A markup issue in admin-dashboard.html was fixed to ensure valid tab navigation.
  • Supporting both user and admin workflows in a static site framework required conditional display logic and clear role separation.

4.3 Reflection

Using Bootstrap and a single brand stylesheet made the project easier to maintain. HTML5 semantics increased accessibility and structure across the site.

The modular JavaScript setup enables future expansion, such as connecting booking workflows to live backend data. Future improvements could include actual image assets, more accessible form labels, and a business landing page.
